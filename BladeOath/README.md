# 暫名待定（代號 BladeOath）

俯瞰式類魂暗黑仙俠動作。畫面是不旋轉的 2D 俯瞰，加上 2.5D 高低差（高台、階梯、落影、遮擋）。一局走完一章：在分岔的地圖裡斬妖練等、湊裝備、點技能樹，沿路打倒數個頭目。戰鬥核心是**格擋、閃避、出招、斷招**，加上被控場時的**脫離**。等級、裝備、技能點只在這一局有效，看懂敵人起手、選對應對方式才是真正變強的方法。

技術基底：PixiJS 8 + GSAP 3；電腦與手機共用一套畫面上的虛擬按鈕。

狀態：**N0 立項（第 3 版草案，待核准）**（2026-11-24）。改版紀錄見 §11。流程狀態：`node shared/tools/loop.mjs status BladeOath`。

## 2. 影片分析：天刀手遊論劍 1v1（太白 vs 太白）

來源：<https://youtu.be/fBTiMqQX00U>（98 秒，PVP 論劍，同門派對打）。逐格看的重點：

| 觀察 | 畫面證據 | 對戰意義 | 本作怎麼用 |
|---|---|---|---|
| **格擋是有冷卻的技能**（格擋[R]，冷卻 16→2 秒輪轉） | 中央跳「擋」字；按鈕上有冷卻數字 | 格擋不能一直開著，交出去就有空窗；什麼時候用格擋本身就是讀招 | **照用冷卻制**（§4），再加一層時機：開格擋的前幾 tick 接到攻擊就是**卸勁**，冷卻大幅退還 |
| **破防**（「破」字） | 被格擋後出招，對方頭上跳「破」 | 格擋可以被專門的招式打穿 | **赤光**招格擋會被破防；玩家的重擊類招式也能破敵人的格擋 |
| **蓄力條**（0.4 秒 / 3.0 秒） | 角色腳下有讀條 | 蓄力招看得見、可以打斷 | **金光讀條**：用帶「斷」標記的招式打中讀條段，敵人大硬直 |
| **浮空與脫離**（浮空[4]、脫離[T]，冷卻 18 秒） | 浮空接連段；脫離是長冷卻的解控 | 控場接連段是主要輸出；解控是保命資源 | **玩家有脫離鍵**（長冷卻）；敵人也有控場招；精英與頭目同樣會用脫離，交掉脫離後才是追擊時機 |
| **突進／位移斬**（突进[5]、長條刀光） | 一條穿越全場的劍氣 | 拉近距離、追擊，也能躲 | 招式之一；俯瞰下可以穿過敵人繞到背後 |
| **破穴大傷害**（「破穴 7879」） | 對方硬直時打出高傷害 | 打出破綻後的懲罰窗口 | **處決**：敵人架勢滿 → 破防 → 處決。條件看得見、每次一樣，**不是暴擊** |
| **鎖定目標** | 選取框跟著對方 | 手機上自動朝向目標 | **軟鎖定**：攻擊自動朝鎖定的敵人；鎖定規則固定（距離＋面向），不隨機 |
| **招式欄 4～6 格、冷卻並行** | 右下技能群＋冷卻數字 | 冷卻管理是輸出循環 | **4 格招式欄**（§4），冷卻以 tick 計、完全固定 |
| 數值碾壓、外觀、聊天頻道 | 跳字幾千、世界頻道 | MMO 的養成與社交 | **不採用**：單機離線，分數不能用錢或時間買（E6） |

結論：這段論劍的核心是「**防守有代價、讀條可以打斷、破綻要懲罰、解控是資源**」，本作四點全部保留。

## 3. 參考：鹽與聖所（Salt and Sanctuary）的成長循環（只借結構）

| 鹽與聖所 | 本作（俯瞰、單局內） | 為什麼這樣改 |
|---|---|---|
| 殺敵得「鹽」，在聖所升級 | 殺敵得**修為**，在**香爐**（存檔點）升級，每升一級得 1 技能點 | 練等只在這一局有效，不帶到下一局 |
| 技能樹（大型網狀） | **技能樹**：一棵共通樹（身法、心法）＋每個流派一棵（§5） | 縮小到一局內點得出差異的大小 |
| 武器類別 | **武器種類決定流派**：劍、刀、槍各自有招式、幀資料與技能樹 | 換武器就是換打法 |
| 死亡時鹽掉在原地，打倒兇手才拿得回 | 倒下 → 回最後一座香爐；修為與**身上裝備**變成「遺骸」，固定掉在**下一個頭目的觸發點之前**（死在頭目手上也一樣）；重生後換回初始武器，**小兵重生，要重新打過小兵區**才能撿回；撿回前再倒一次，舊遺骸消失、換成新的（已定案） | 類魂的撿屍體；掉落點固定，不會掉進頭目房讓人撿不到；完全確定性 |
| 休息會讓敵人重生 | 在香爐升級時，小兵在**固定位置**重生 | 想多練就花時間，會吃掉時間分 |
| 裝備重量影響翻滾 | 武器與護具有**負重**：重 → 閃避距離短、架勢強 | 選裝備就是取捨 |
| 隨機掉落、稀有度 | **固定掉落**：每個精英、每個頭目、每個寶箱給什麼，在同一章一定一樣 | 去隨機化（[01 §3](../knowledge-base/01_skill-integrity.md)） |
| 局外養成、跨周目 | **不採用** | 上架規範：結果不能取決於累積了多少時間 |

## 4. 戰鬥

### 4.1 敵人起手光色

| 起手光色 | 意思 | 正解 | 錯解的代價 |
|---|---|---|---|
| 白光 | 一般招 | 格擋（壓時機就是卸勁） | 被打中 |
| 金光＋讀條 | 蓄力招 | 讀條內用「斷」標記的招式打斷 | 蓄滿後出強招（還是可以閃） |
| 赤光 | 霸體或控場 | **閃避**（壓線閃避就是完美閃避） | 格擋被破防；中了控場只能靠脫離 |

### 4.2 玩家動作與按鈕（共 8 顆）

| 按鈕 | 電腦鍵盤 | 機制 | 成功效果 | 代價 |
|---|---|---|---|---|
| **普攻** | `J` | 連段 3 下 | 傷害＋削架勢 | 收招時會被打 |
| **格擋** | `K` | **冷卻制**：按下開一段格擋時間，結束後進冷卻 | 擋下攻擊、扣少量架勢；開擋前幾 tick 接到攻擊＝**卸勁**：不扣架勢、敵人架勢大增、冷卻大幅退還、得內力 | 交出去就有空窗；擋赤光會被破防 |
| **閃避** | `Space` | 往移動方向閃，耗體力 | 無敵幀；壓線＝**完美閃避**，給反擊窗口與內力 | 體力不足不能閃；越重閃越短 |
| **招式 1–4** | `U` `I` `O` `P` | 4 格招式欄，各自冷卻；部分招式耗內力 | 依招式：突進、浮空、範圍、破架…；帶「**斷**」標記的招式打中金光讀條＝斷招 | 打空有收招；斷招打在赤光上沒有效 |
| **脫離** | `L` | 長冷卻；被硬直或控場時也能按 | 立刻解除控場並短距離後撤 | 冷卻很長，交掉就沒有保命手段 |

- 每一招都有固定的幀資料（起手、判定、收招各幾 tick），冷卻以 tick 計，同一招每次一樣（E5）。
- 雙方都有**架勢**：防守打得好會讓敵人先崩，崩了可以**處決**。
- 俯瞰下面向很重要：**繞到背後**打，架勢傷害加倍；敵人轉身速度固定。
- 精英與頭目也有脫離；騙出敵人的脫離後再控場，是頭目戰的高階打法。

## 5. 成長：等級、技能樹、流派、裝備

| 系統 | 內容 | 公平性 |
|---|---|---|
| 修為與等級 | 殺敵得修為（每種敵人固定值），在香爐升級 | 敵人與數值固定 |
| 技能樹 | 每升一級 1 點。**共通樹**：體力、閃避距離、卸勁窗口、脫離冷卻等；**流派樹**：解鎖該流派的招式與強化 | 每個節點效果固定、公開；可在香爐重置（只花時間） |
| 流派＝武器種類 | **劍**：出手快、「斷」招多，偏卸勁與斷招；**刀**：慢而重、破架強，偏處決；**槍**：攻擊距離長、突進多，偏走位與繞背 | 三種各有強弱，沒有最強流派；N5 用技巧證據檢查 |
| 招式欄 | 從已解鎖的招式中選 4 招放上去，只能在香爐改 | — |
| 裝備 | 武器（決定流派）＋護具（負重與防禦）；精英、頭目、寶箱掉固定裝備；鍛材在香爐強化武器 | 掉落表固定，同一章一樣 |

## 6. 地圖與章節（第一章）

地圖比較大、有岔路；岔路都是**可選的**：走進去能多拿裝備或修為，但花時間（`planning`）。

```
            ┌─▶ 蠱林（精英：蠱母，掉落：刀）─┐
 山門 ─▶ 香爐① ┤                              ├─▶ 中頭目①：屍傀將 ─▶ 香爐②
 （小兵）       └─▶ 枯井（寶箱：槍、鍛材）──────┘
                                                        │
     ┌──────────────────────────────────────────────────┘
     ▼
 斷崖棧道（2.5D 高台；岔路：崖下洞窟，精英＋鍛材）─▶ 中頭目②：縛魂鬼面 ─▶ 香爐③ ─▶ 終頭目：墮仙
```

| 區段 | 新加的一件事 | 固定掉落 |
|---|---|---|
| 山門 | 只有白光小兵 | 修為、初始劍升級材料 |
| 蠱林／枯井（擇一或都走） | 金光讀條；蠱林精英 | 刀／槍（換流派的機會） |
| 中頭目① 屍傀將 | 第一個頭目：白＋金，會用脫離 | 護具、大量修為 |
| 斷崖棧道 | 赤光；被擊退到高台邊緣會摔落（扣血、不會即死） | 鍛材；崖下洞窟另有精英 |
| 中頭目② 縛魂鬼面 | 控場招（赤光），考驗脫離 | 第二件護具 |
| 終頭目 墮仙 | 三色混用、半血後換招表 | — |

- 難度只升不降（`RULE-CURVE-*`、[16_difficulty-curve](../knowledge-base/16_difficulty-curve.md)）：每區只加一件事。
- 種子只決定同一難度級內的小兵配置、巡邏順序與外觀；同一題每個人一樣。地圖骨架、岔路、精英、頭目、掉落每次一樣。
- 遺骸掉在**下一個還沒打倒的頭目**的觸發點前。
- 地圖變大但局長仍是 4–6 分鐘：主線約 3–4 分鐘，岔路各約 30–60 秒，全部走完會擠到上限。N2 用試玩 bot 量。
- 之後多章是「多張題目」，每章各自一局，不繼承等級與裝備。

## 7. 操作：虛擬按鈕在電腦與手機共用

畫面上的按鈕是唯一一套 UI（DOM 疊在 canvas 上），三種裝置都由同一層把輸入換成 sim 的 1 byte：

| 裝置 | 移動 | 動作 | 注意 |
|---|---|---|---|
| 手機觸控 | 左下浮動搖桿 | 右下 8 顆按鈕（普攻大鈕居中，招式 1–4 環繞，格擋、閃避、脫離在拇指好按的位置；多點觸控，可以邊走邊按） | 按鈕上顯示冷卻數字；大小 ≥ 拇指，間距防誤觸 |
| 電腦鍵盤 | `WASD`／方向鍵 | 按鈕上印鍵帽（`J` `K` `Space` `U` `I` `O` `P` `L`）；按實體鍵時虛擬按鈕同步亮起、播一樣的回饋 | 教學只教一次，鍵位印在按鈕上 |
| 電腦只用滑鼠 | **點地面移動**（走到點擊位置，按住就持續跟著游標） | 點虛擬按鈕；按鈕有 hover 與按下狀態 | 滑鼠一次只能點一個位置，所以移動改成點地面，不做拖曳搖桿；攻擊自動朝向鎖定目標 |

- 輸入一律走範本的 `InputClock`／`TapQueue`（[13_input-fairness](../knowledge-base/13_input-fairness.md)）：以事件時間戳決定在哪一個 tick 生效，跟幀率無關。卸勁窗口很短，這是公平的前提。
- 三種輸入在 sim 看到的都是同一組位元；裝置類型寫進 `rec.meta`，N9 試玩時分開看命中率。

## 8. 計分（E4：標題與結算逐項列出）

分數只來自玩家行為：擊倒頭目（每個頭目基本分，終頭目最高）、剩餘時間、卸勁、完美閃避、斷招、處決次數。倒下不另外扣分，代價已經算在時間與重打小兵裡。等級與裝備不直接加分，只讓你打得過；練太久、岔路走太多會吃掉時間分。沒有暴擊、沒有隨機掉落、沒有局外加成。確切公式與數值在 N2 的 `gdd/05_game_spec.md`。

## 9. 技術架構（細節在 N2／N3，這裡只定分層）

```
觸控／鍵盤／滑鼠 ─▶ 虛擬按鈕層（DOM）─▶ InputClock ─▶ 每 tick 1 byte ─▶ sim（60 Hz 確定性）─▶ events ─▶ render / fx / audio / ui
                                                                           │
                                                                    Recorder → verify() 重播驗分
```

| 層 | 內容 | 規則 |
|---|---|---|
| 輸入 1 byte | 移動 4 位元（8 方向 3 位元＋「有在移動」1 位元）＋動作 4 位元（無、普攻、格擋、閃避、招式 1–4、脫離 = 9 種；同一 tick 只送一個動作，多的排到下一 tick） | sim 只吃這 1 byte；滑鼠座標只給演出用 |
| `sim/` | 角色狀態機（待機／移動／起手／判定／收招／硬直／控場／破防／倒地）、4 方向幀資料表、軸對齊判定框、氣血／體力／架勢／內力、冷卻（tick）、修為／等級／技能樹、流派與招式表、固定掉落表、遺骸、敵人招式腳本與巡邏、香爐與重生、計分 | `RULE-SIM-PURITY`；只用 `sim/core/`（rng、fixed、grid） |
| 地形 2.5D | 範本的 `core/grid.js`（高台格）＋ `render/terrain.js`（2.5D 投影、遮擋片）＋ `render/xray.js`（被擋住時的輪廓）；鏡頭捲動 | sim 碰撞與畫面用同一張格子 |
| `render/` | PixiJS 8：4 方向像素 sprite（不旋轉圖）、y 排序、落影 | 基礎 DC ≤ 5（`RULE-DRAWCALL-2D`）；角色、敵人、特效同一張 atlas；地圖分區載入 |
| `fx/` | 卸勁火花、刀光、斷招碎光、hit-stop（只停 render）、震動、妖氣 | 數值全在 `fx/feel.js` 的 `FEEL`；尊重降低特效 |
| `audio/` | Web Audio 合成：金屬撞擊、刀風、低頻環境 | 盡量 0 bytes 音檔 |
| `ui/` | DOM：虛擬搖桿與 8 顆按鈕（含冷卻）、氣血／體力／架勢／內力、香爐面板（升級、技能樹、招式欄、鍛造） | UI 一律 HTML/CSS；香爐面板開啟時 sim 暫停（記進輸入紀錄） |
| 打包 | 單檔 `index.html` zip，file:// 可開 | `RULE-BUNDLE-SIZE`、`RULE-NO-RUNTIME-CDN` |

AI 不擲骰：小兵巡邏、進攻時機、出哪招、何時用脫離，由腳本加種子排序決定；對玩家行為的反應（被斷招後換招、玩家繞背時轉身）是固定規則。

## 10. 立項檢核（RULE-LEGAL-EXCLUDE-CHANCE）

| 2 | 傳統博弈形式 | 仙俠動作，沒有任何博弈外觀或用語 | 不落入 |

其他立項確認：

- 精髓七條（[01_skill-integrity §2](../knowledge-base/01_skill-integrity.md)）：E1 分數只來自玩家行為；E2 同種子同配置同掉落；E3 固定視野範圍；E4 三色起手＋結算逐項列出；E5 固定幀資料與冷卻、可以重玩同一題；E6 等級、技能點、裝備只在局內，沒有付費、沒有局外養成；E7 用輸入紀錄重播驗分。逐條答案寫在 N2 的 gdd/05 §10。
- **練等衝裝與技巧主導**：等級、技能、裝備會讓人更好打，但取得它要花局內時間，而且來源完全固定，所以它是 `planning` 技巧，不是運氣。N5 用技巧證據驗證「同樣的路線與配點下，操作好的贏操作差的」，也檢查三個流派沒有一個明顯最強。
- **台灣美術禁忌**（`RULE-ART-TW-TABOO`）：暗黑仙俠**不畫現行宗教的神明、神像、廟宇、法器**（不用佛寺、僧人、道觀、符籙作為主視覺）；場景用虛構仙門的廢墟，頭目是虛構妖物與墮落的仙人（原創，不是任何信仰的神明）。不戴綠色頭飾、避免大面積純黑（暗色調用深藍灰、墨綠以外的暗色），N6 每張圖人工驗收。
- 參考遊戲（[15_reference-games](../knowledge-base/15_reference-games.md)）：參考作違反三原則的做法（`Math.random`、可變 dt、局外加成乘分數）本作一律不採用。
- 授權（[06_art-pipeline §5](../knowledge-base/06_art-pipeline.md)）：《天涯明月刀手遊》與《鹽與聖所》只作戰鬥與成長**結構**參考，不使用其名稱、角色、招式名、畫面或音樂。
- 上架規範：單機離線、觸控可玩、電腦可以只用滑鼠或只用鍵盤、單檔 zip、≤ 10 MB。
