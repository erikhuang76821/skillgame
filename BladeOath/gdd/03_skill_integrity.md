# 03 技巧完整性

> 方法：[01_skill-integrity](../../knowledge-base/01_skill-integrity.md)（三問、精髓七條、去隨機化、技巧證據）、[03_design-patterns §2](../../knowledge-base/03_design-patterns.md)（公平模式）、[13_input-fairness](../../knowledge-base/13_input-fairness.md)（輸入公平）、[04_tech-stack §4](../../knowledge-base/04_tech-stack.md)（確定性）、[16_difficulty-curve §3](../../knowledge-base/16_difficulty-curve.md)（人性化試玩）。立項內容見 [README](../README.md)；精髓七條的逐條答案在 N2 寫進 [05 §10](05_game_spec.md)。

本作是動作類，但有局內成長（修為、技能樹、裝備）與分岔地圖，隨機最容易從「掉落」「敵人 AI」「暴擊」三處混進來。原則：**所有可能影響分數的事，不是固定的，就是玩家造成的；種子只決定同一難度級內的配置。**

## 1. 每個系統的三問

| 系統 | 有沒有玩家控制不了、但會影響分數的東西？ | 條件是否完全相同？ | 能不能拿出證據？ |
|---|---|---|---|
| 地圖骨架 | 沒有。區段、岔路、劍塚、精英、頭目位置每章固定 | 相同 | 地圖資料是 sim 常數；stateHash 含地圖雜湊 |
| 小兵配置 | 種子決定同一難度級內「哪幾隻、站哪幾個預設點、巡邏起始相位」 | 同種子相同 | 重播；測試比對兩種玩法下的配置表 |
| 小兵重生 | 在劍塚休息或玩家倒下時，**回到開局排好的同一配置**，不重抽 | 相同 | 測試：重生前後配置表相同 |
| 敵人出招 | 招式表固定；第 *k* 輪的出招順序 = `rng.shuffle(seed, 'combo:' + 敵人id, k)`，只在同一難度級的招式池內排序 | 同種子相同 | 重播 |
| 敵人反應 | 固定規則，看的是玩家當下狀態（距離、面向、是否在格擋、是否剛被斷招），沒有機率 | 相同（玩家可控） | 重播 |
| 敵人脫離 | 精英與頭目的脫離是固定冷卻＋固定觸發條件（被控場第 n tick），不是機率 | 相同 | 重播 |
| 鎖定目標 | 規則固定：先看距離，再看是否在面向的 90° 內，平手看 id 小的 | 相同 | 重播 |
| 傷害與架勢 | 固定值 × 固定倍率（繞背、處決、流派、技能節點），**沒有暴擊、沒有浮動** | 相同 | 結算逐項；單元測試 |
| 卸勁、完美閃避 | 窗口以 tick 計、長度固定；輸入照事件時間戳歸到所屬 tick | 相同（幀率無關） | `InputClock` 測試：30／60／120／144 Hz 產生同一份輸入紀錄 |
| 冷卻 | 以 tick 計；卸勁退還冷卻的量固定 | 相同 | 重播 |
| 修為與等級 | 每種敵人給固定修為；同一隻小兵每被重生打倒一次，修為依固定表遞減（防無限刷） | 相同 | 修為表是常數 |
| 技能樹 | 節點效果固定、公開；配點是玩家選擇；劍塚可重置（只花時間） | 相同 | 選擇紀錄隨重播上傳 |
| 掉落與寶箱 | 每個精英、頭目、寶箱給什麼是常數，**不看種子**；小兵掉的鍛材也是固定量 | 所有人相同 | 掉落表是常數；測試 |
| 倒下重來 | 回本關開頭劍塚，整關用同一批 index 重來（同敵種、同進場側與延遲） | 相同（玩家可控） | 重播 |
| 關卡與障礙物 | 關長、戰區、障礙物、破壞物與掉落都是關卡常數；擊退距離固定 | 相同 | 重播 |
| 時間 | 局內計時以 tick 計；劍塚面板與暫停時 sim 不走、時間也不走 | 相同 | 重播 |
| 計分 | 只來自擊倒頭目、剩餘時間、卸勁、完美閃避、斷招、處決 | 相同 | 結算逐項列出；理論上限可算 |
| 輸入 | 三種裝置都換成同一組位元（8 方向＋9 種動作），每 tick 1 byte | 規則相同；裝置差異在 N9 量 | 輸入紀錄逐 byte 上傳 |

## 2. 去隨機化對照

| 隨機來源 | 一般類魂／ARPG 做法 | 本作 |
|---|---|---|
| 敵人生成 | 隨機刷怪、隨機菁英詞綴 | 地圖骨架固定；小兵配置 = 同難度級池子以 `rng.shuffle(seed, 'spawn', 區段)` 排序後依序放到預設點；開局排定，之後不再抽 |
| 敵人 AI | 加權隨機選招、隨機延遲 | 出招順序是同難度級內的固定招式池，第 *k* 輪 `rng.shuffle(seed, 'combo:' + id, k)`；起手間隔固定；對玩家的反應是規則 |
| 掉落 | 機率掉落、稀有度、詞綴 | **全部固定**：精英、頭目、寶箱給的裝備不看種子；沒有稀有度與詞綴 |
| 暴擊、閃避率、格擋率 | 機率 | 取消。「破穴」式的高傷改成處決：架勢滿 → 破防 → 處決，條件看得見 |
| 傷害浮動 | ±10% | 取消；固定值 |
| 升級選項 | 隨機三選一 | 技能樹全部公開，想點哪就點哪；沒有隨機選項 |
| 死亡懲罰 | 掉落位置隨死亡點 | v5 沒有遺骸；倒下只損失時間（整關重來） |
| 敵人重生 | 隨機重刷 | 重生回到開局排好的同一配置 |
| 控場時間 | 隨機解控 | 固定 tick；玩家脫離是主動按鍵 |
| 動態難度 | 依玩家表現調整 | 沒有。難度只由腳本與區段決定，難度只升不降 |
| 局外加成 | 等級、裝備、天賦帶到下一局 | 全部沒有；每局從同樣的初始狀態開始 |

RNG 一律用無狀態雜湊，index 是事件序號（第幾區段、第幾隻敵人、第幾輪出招），不是呼叫次數；所以玩家打得快或慢、走哪條岔路，都不會讓其他地方的序列錯位。

## 3. 技巧來源（高手比中手多拿分的地方）

1. **讀招（reaction）**：看白／金／赤光選對應。選錯的代價是被破防、被打斷不到、被控場，選對才會有卸勁、斷招、完美閃避的分。
2. **時機（timing）**：卸勁與完美閃避的窗口比普通格擋與閃避窄，拿到的分、內力、退還的冷卻都更多。這是風險換報酬：壓時機失敗就是吃滿傷。
3. **走位（aim）**：v5 橫向卷軸：深度軸上錯開就打不到（也被打不到）；繞到背後架勢加倍；一群小兵時避免被一左一右包夾；把小兵摔進人群、把敵人擊退撞上障礙物。
4. **資源管理（planning）**：格擋、脫離、招式的冷卻與體力、內力都有限；什麼時候交脫離、什麼時候搶攻，決定能不能撐過頭目的控場段。
5. **路線與成長規劃（planning）**：岔路要不要走、要練多久、點哪條技能樹、換哪個流派。練得越多越好打，但時間分越少；最高分是「剛好夠用」的路線，而不是練滿。

## 4. 已知風險與對策

| 風險 | 來源 | 對策 |
|---|---|---|
| **練滿再打**：刷小兵練到很高等，任何操作都能輾過頭目，技巧變成「花時間」 | 本作設計（使用者要求的練等衝裝） | ① 同一隻小兵每次重生後打倒的修為依固定表遞減；② 每章有等級上限；③ 剩餘時間佔分數一大塊；④ N5 簡單策略之一就是「刷到上限再一路普攻」，由 `RULE-SKILL-BEATS-SIMPLE` 擋 |
| **只會擋**：遇到攻擊就按格擋，不看光色 | 天刀論劍「格擋」與類魂常見打法 | 格擋是冷卻制、交出去有空窗；赤光會破防；N5 簡單策略「見起手就格擋」 |
| **只會閃**：一直閃避 | 同上 | 閃避耗體力；完美閃避窗口窄才給分；N5 簡單策略「見起手就閃避」 |
| **狂按普攻** | 一般動作遊戲 | 敵人白光格擋會彈刀、硬直；N5 簡單策略「一直普攻」 |
| 有一個流派明顯最強 | 本作設計（流派＝武器） | N5 報告列出三個流派的強策略平均分；某個流派在所有題目都最好就回 N2 改流派 |
| 有一條技能樹配點永遠最好 | 本作設計 | 同上，列出幾種固定配點的平均分；節點效果改在 N2 規格調 |
| 障礙物卡位（敵人卡在障礙物後打不到玩家，或玩家被障礙物夾住） | 障礙物佈置與 AI | 不可破壞障礙物佔深度 ≤ 一半、留通道；敵人對位時繞開障礙物；N4 測試佈置規則 |
| 故意倒下刷修為 | 倒下後整關重來 | 同配置點修為與技巧分依 `XP_DECAY_PCT` 遞減，第 4 次以後為 0；倒下只損失時間 |
| 劍塚面板或暫停當作思考時間 | 暫停 | 劍塚只能在戰鬥外使用；戰鬥中暫停時畫面遮住、不能逐格看招；暫停次數有上限（N2 定值） |
| 鎖定目標不如玩家預期 | 軟鎖定 | 規則固定、公開，畫面一直標出目前鎖定的敵人 |
| 三種輸入裝置有落差（只用滑鼠的人走位比較慢） | 電腦虛擬按鈕 | sim 只看同一組位元，規則相同；點地面移動換成 8 方向是確定性的；N9 依裝置分開看命中率，差太多就改操作設計（不是改計分） |
| 卸勁窗口太窄，受幀率與裝置延遲影響 | [13 §1](../../knowledge-base/13_input-fairness.md) | 輸入用事件時間戳歸 tick；窗口設計 ≥ 6 tick（約 100 ms），1 tick 的解析度就夠，不需要子 tick 相位（輸入 byte 已用滿 8 位元）。校正（`calibrate()`）是否需要，N2 依窗口長度決定 |
| 一局 4–6 分鐘，題目間差異大 | 局長 | 排行只比同一題；跨題用百分位 |
| 巨集或輔助程式（自動卸勁） | [13 §4](../../knowledge-base/13_input-fairness.md) | 伺服器重播驗分；卸勁時機的誤差分布過窄時標記（`errorSuspicion`），門檻待真人資料 |
| 跨引擎結果不同 | [04 §4](../../knowledge-base/04_tech-stack.md) | 位置用整數子像素、方向查表、距離比平方；判定框軸對齊；固定種子的 golden match 測試 |

## 5. N5 要準備的比較策略（先列，N4 寫成 `tools/strategies.mjs`）

| 角色 | 策略 | 看得到什麼 | 能力限制 |
|---|---|---|---|
| 強 | 讀光色選正解、壓時機、繞背、走主線＋值得的岔路、照固定配點 | 與真人相同的畫面資訊 | 反應時間與時機誤差照人性化模型的「熟手」 |
| 隨機 | 每 tick 隨機選方向與動作（用自己的種子，不影響題目） | — | — |
| 簡單 | ①一直普攻；②見起手就格擋；③見起手就閃避；④刷到等級上限再一路普攻 | 只看「敵人有沒有在起手」，不看光色 | 時機不壓線 |

第一批門檻由 `RULE-SKILL-EVIDENCE`、`RULE-SKILL-NOT-LUCK`、`RULE-SKILL-BEATS-SIMPLE` 決定，數值只在 `knowledge-base/index/rules.json`。
