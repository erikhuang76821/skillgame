# 12 對戰架構 v3

> 狀態：**方向已核准**（2026-11-24，使用者：照建議進行），規格寫進 gdd/05 §5.0，待 N2 核准。使用者回饋：目前戰鬥「太粗糙」，要補上**物理攻擊、攻擊動態、骨架**，參考 Hades。本文件定義架構；核准後走迴圈回退到 N2（改 gdd/05 §5），再依序重做 N4 sim、N5 調校、N7 畫面。
> 原則不變：sim 確定性（`RULE-SIM-PURITY`）、技巧主導、預警＝判定（[19 §3](../../knowledge-base/19_vfx-spec-templates.md)）、打擊感只在 render（[05](../../knowledge-base/05_juice-and-feel.md)）。

## 0. 現在缺什麼

| 面向 | 現況（v2） | 問題 |
|---|---|---|
| 判定 | 一個軸對齊矩形，整段判定期間不動 | 橫掃與直刺打起來一樣；看不出「刀從哪裡劃過」 |
| 位移 | 只有「突進」平移；被打只往後推固定格數 | 沒有重量感；不能把敵人打飛撞牆、推下高台 |
| 身體 | 角色互相穿過 | 被圍時位置關係沒意義；無法卡位、繞背沒有代價 |
| 方向 | 4 方向 | 斜向攻擊打不到；面向與鎖定很生硬 |
| 動作 | 起手／判定／收招三段，沒有取消規則 | 一出手就鎖死；沒有「收招能閃開」的高手空間 |
| 動畫 | 色塊＋一根線 | 看不出起手姿勢，讀招只能靠光圈 |

## 1. 參考：Hades 的戰鬥結構（只借結構，不借名稱、角色、美術、數值）

| Hades 的做法 | 它帶來什麼 | 本作怎麼用 | 與類魂取向的調整 |
|---|---|---|---|
| 攻擊附帶**前衝**（每一段連擊都往前踏） | 攻擊有重量、能追擊 | 每招的 `lunge` 曲線（§3） | 前衝距離短，收招不可取消前衝 |
| **衝刺**可以取消攻擊收招、衝刺中無敵 | 節奏快、高手空間 | 閃避可以取消收招，但只在每招指定的**取消窗**之後，且耗體力 | 取消窗比 Hades 晚：出手仍有代價 |
| **衝刺斬**（衝刺中按攻擊＝專用招式） | 攻防一體 | 閃避後 8 tick 內按攻擊＝「回身斬」 | 只在完美閃避後才有額外架勢傷害 |
| 敵人**擊退**、撞牆／撞陷阱有額外傷害 | 場地變成武器 | 擊退有質量；撞牆＝「撞壁」傷害＋硬直；推下高台＝墜落 | 頭目質量大、幾乎推不動 |
| 敵人有**護甲條**，打破才吃全傷害並硬直 | 目標明確 | 已有「架勢」，改成「架勢滿＝破防＝可處決」，再加**韌性**（單擊硬直門檻） | 同上 |
| 地面**預警圖形**（圓、扇形、直線） | 讀招靠形狀 | 預警圖形由判定形狀直接畫（§4） | 光色仍是主要規則 |
| 命中**白閃＋短停頓＋傷害數字** | 打擊感 | render 層，數值在 `FEEL`（§7） | — |
| 攻擊方向跟著準星／右搖桿 | 移動與攻擊分離 | **不加瞄準位元**（輸入 byte 已滿、core 不改）：攻擊朝軟鎖定目標，沒有目標時朝移動方向 | 以鎖定規則補足 |

## 2. 架構總覽

```
            sim/（確定性，60 Hz）                                   render/（不回寫 sim）
 ┌──────────────────────────────────────────┐        ┌──────────────────────────────────────┐
 │ input byte → Intent（移動方向、動作、緩衝） │        │ Rig：程式骨架（14 根骨）               │
 │ ActionState：招式時間軸（§3）               │ events │ Pose：由 sim 的招式 id + 第幾 tick 取姿勢 │
 │ Body：位置 x,y,z、速度、半徑、質量（§5）     │ ─────▶ │ Locomotion：由速度取步伐                │
 │ Hit：判定形狀 × 受擊圈、命中規則（§4）       │        │ Reaction：受擊、擊退、破防、倒地（疊加）  │
 │ Status：架勢、韌性、硬直、無敵、霸體        │        │ VFX：刀光拖尾、白閃、塵土、預警圖形       │
 │ AI：追蹤→出手承諾點→招式時間軸               │        │ Camera：跟隨＋命中方向的小推移            │
 └──────────────────────────────────────────┘        └──────────────────────────────────────┘
```

關鍵：**動畫由 sim 的招式時間軸驅動**（同一份資料決定判定與姿勢），所以看到的起手姿勢一定對應真正的出手時間；不會出現「動畫跟判定對不上」。

## 3. 招式時間軸（Move Timeline）

每一招是一份資料，所有數字以 tick 為單位：

```js
{ id: 'sword.combo1', glow: 0,
  phases: { startup: 6, active: 4, recover: 14 },          // 起手（預備動作）/ 判定 / 收招
  track:   { until: 4, turn: 16 },                           // 起手前 4 tick 還能轉向（每 tick 最多 16/256 圈），之後承諾
  lunge:   [[0, 0], [6, 0], [8, 18], [10, 22]],              // 根位移（像素）沿面向，關鍵點之間線性
  hits: [                                                    // 判定關鍵格：形狀隨時間移動 = 刀劃過的軌跡
    { t: 6, shape: 'arc', r: 26, from: -60, to: 0,   dmg: 8, pos: 6, force: 90, group: 0 },
    { t: 8, shape: 'arc', r: 26, from: 0,   to: 60,  group: 0 },   // 同一 group 對同一目標只中一次
  ],
  armor:  null,                                              // 霸體區間 [from, to]（受擊不硬直）
  iframe: null,                                              // 無敵區間
  cancel: { dodge: 12, combo: 10, skill: 12 },               // 從第幾 tick 起可以被閃避／下一段／招式取消
  pose:   'sword.slashR',                                    // 姿勢組（render 用；sim 不讀）
}
```

| 欄位 | 作用 | 技巧意義 |
|---|---|---|
| `track` | 起手前段跟著目標轉，過了承諾點就不轉 | 敵人：晚閃才有用（壓線）；玩家：出手後不能亂轉 |
| `lunge` | 招式自帶位移 | 距離管理；連擊會把自己帶進敵群 |
| `hits` | 判定是**一連串形狀**（扇形、矩形、圓、膠囊），每格可不同 | 橫掃有左右先後，站對邊可以晚一點才被掃到 |
| `cancel.dodge` | 收招中多早可以閃 | 高手可以「打完立刻閃」，新手被收招卡住 |
| `armor` | 霸體 | 赤光招的本質＝起手到判定都有霸體 |

**輸入緩衝**沿用 `BUFFER_TICKS`；取消窗開啟的那一 tick 立刻執行緩衝中的動作。

## 4. 判定與受擊

| 形狀 | 參數 | 用在 |
|---|---|---|
| `arc` 扇形 | 半徑、起訖角（相對面向，256 分度） | 橫掃、揮砍 |
| `rect` 矩形 | 長、寬（沿面向） | 直刺、劍氣 |
| `circle` 圓 | 半徑、中心偏移 | 範圍招、落地衝擊 |
| `capsule` 膠囊 | 起點、終點、半徑 | 突進（沿位移路徑掃過，不會「穿過」目標） |

- 受擊圈：每個身體一個圓（半徑 = 身體半徑）。判定用整數：扇形用平方距離＋查表角度（`angleOf`），不用三角函數。
- 命中規則：同一招、同一 `group` 對同一目標只中一次；不同 group 可再中（多段招）。
- **拼刀**：玩家與敵人的判定在同一 tick 互相重疊，而且都是白光 → 雙方彈開（`clash`），都不受傷、都加架勢；這是卸勁之外的第二種「讀到了」。
- 背擊：攻擊方位在目標面向的後方 120° 內（原本 180°），架勢 ×2。

## 5. 身體與物理（確定性）

| 欄位 | 說明 |
|---|---|
| `x, y` | 子像素（1/256） |
| `z, vz` | 高度與垂直速度（浮空、擊飛；落地有硬直） |
| `vx, vy` | 速度；每 tick 乘摩擦（整數比例，例 `FRICTION` = 200/256） |
| `r` | 身體半徑；身體之間會互相推開 |
| `mass` | 質量：小兵 1、力士 3、精英 4、頭目 8、玩家 2 |

每 tick 順序：

1. 招式根位移（`lunge`）與移動意圖 → 速度
2. 擊退衝量：`v += force × 方向 / mass`（方向 = 攻擊者面向，或圓形判定時由中心向外）
3. 積分、牆壁滑動、高度規則（沿用 `stepLevel`）
4. **撞壁**：擊退速度超過 `SLAM_SPEED` 撞上牆 → 撞壁傷害＋`SLAM_STUN` 硬直（敵人與玩家都適用）
5. **墜落**：被擊退越過高台邊緣 → 墜落傷害＋硬直（已有）
6. **身體分離**：依 id 順序兩兩檢查重疊，按質量比例推開（固定順序，所以確定性）

這讓「把力士撞向牆」「把蠱師推下迴廊高台」變成可規劃的技巧，也讓被包圍真的危險。

## 6. 狀態：架勢、韌性、霸體

| 量 | 規則 | 結果 |
|---|---|---|
| 架勢（已有） | 累積到滿 → 破防 120 tick → 任何一擊＝處決 | 長期目標 |
| **韌性**（新） | 單擊的 `force` ≥ 目標韌性 → 硬直（打斷出手）；小於 → 只吃傷害 | 小兵一刀就斷，力士要重擊或背擊 |
| 霸體 | 招式 `armor` 區間內不吃硬直 | 赤光招 = 霸體；只能閃 |
| 浮空 | 挑空類招式給 `vz`；空中無法出招，落地硬直 | 連段起點 |

## 7. 骨架（render 層，程式繪製）

### 7.1 骨架

| 骨 | 父 | 說明 |
|---|---|---|
| root | — | 腳底，跟 sim 的 x,y；z 只抬高身體、影子留在地上 |
| pelvis | root | 走路上下起伏 |
| spine → chest → head | pelvis | 預備動作時後仰、出手時前傾 |
| upperArmR → foreArmR → handR → weapon | chest | 持劍手；刀尖位置決定刀光拖尾 |
| upperArmL → foreArmL → handL | chest | 平衡手 |
| thighR/L → shinR/L → footR/L | pelvis | 步伐、弓步 |

- 每根骨是一個小 sprite（膠囊、圓），全部在同一張 atlas → 一個角色仍是同一批 Draw Call。N6 的像素美術改成「分件剪紙」（頭、身、手臂、腿、武器）掛到同一組骨。
- **方向**：8 方向；左右鏡像，實際只做「下、斜下、側、斜上、上」5 組姿勢。鏡頭與整張圖都不旋轉，轉的是骨頭。
- 繪製順序依方向切換（面向上時武器手在身體後）。

### 7.2 姿勢從哪來

| 狀態 | 姿勢來源 | 同步方式 |
|---|---|---|
| 起手 | 招式的 `pose` 組：`anticipation` 關鍵姿勢，從 0 補間到起手最後一 tick | 起手越長、預備越明顯（讀招的視覺線索） |
| 判定 | `strike` 關鍵姿勢；刀尖沿判定關鍵格的角度掃過 | 刀光 = 判定形狀 |
| 收招 | `follow` → 回到站姿；取消窗開啟時身上閃一下 | 告訴玩家「現在可以閃了」 |
| 移動 | 依速度選步伐週期（走、跑），步幅 = 速度 | 由 sim 速度算，不另外存 |
| 受擊 | 疊加姿勢：往擊退方向後仰，強度依 `force` | — |
| 破防／倒地／浮空 | 專用姿勢；浮空時整個骨架隨 z 抬高 | — |

姿勢是**關鍵格資料**（`render/poses.js`），由 `poseAt(moveId, phase, tickInPhase)` 計算，緩動用固定曲線（不用 GSAP，因為要跟 tick 同步）。GSAP 只做 UI、鏡頭與白閃。

## 8. 打擊感（render，數值在 `FEEL`）

| 事件 | 效果 |
|---|---|
| 命中 | 目標白閃 2 幀、停頓（依傷害分三級）、往擊退方向的小震動、刀光拖尾 |
| 擊退 | 腳下塵土拖痕；撞壁時牆面裂痕＋大震動 |
| 拼刀 | 火花、雙方後退、金屬音 |
| 卸勁 | 現有效果＋敵人武器被彈開的姿勢 |
| 處決 | 慢動作 0.15 秒（只停 render）、鏡頭推近 |
| 取消窗開啟 | 玩家身上一道細光（可關閉的輔助提示） |

## 9. 敵人行為（沿用固定規則，加上物理）

- 出招前段追蹤、過承諾點後鎖定方向（`track`）；這是「壓線閃避」能成立的原因。
- 攻擊權杖：同時最多 `MAX_ATTACKERS` 個敵人在起手或判定中（已有）。
- 包圍站位：沒拿到權杖的敵人在玩家周圍固定的槽位上繞圈（依 id 分配槽位，確定性）。
- 預警圖形直接用招式的判定形狀畫（扇形、直線、圓），顏色＝光色。

## 10. 對現有系統的影響

| 項目 | 變動 |
|---|---|
| sim | 新增身體物理、招式時間軸、多形狀判定、韌性、拼刀、撞壁、8 方向；`GAME.version` 3 |
| 輸入 | 不變（1 byte）；攻擊方向由軟鎖定決定 |
| 規格 | gdd/05 §1（狀態欄位）、§5（規則）、§11（事件→演出）改寫；新增常數 `FRICTION`、`SLAM_SPEED`、`SLAM_STUN`、`CLASH_PUSH` 等 |
| 測試 | 物理確定性、取消窗邊界、拼刀、撞壁、身體分離不穿模；「沒有躲不掉的傷害」改用新判定形狀重算 |

| 效能 | 身體兩兩分離 O(n²)：只模擬玩家附近的敵人（已有），n ≤ 12，可接受 |
| 包體 | 骨架與姿勢都是程式與資料，約 +30 KB |
